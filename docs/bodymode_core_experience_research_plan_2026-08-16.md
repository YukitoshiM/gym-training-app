## 1. 目的

次の実装判断に必要な事実を集め、仮説と確認済み事項を分離する。

- 今日提示すべき行動と頻度
- 目的、経験、回復状態による行動の違い
- AIが計画を変更すべき条件と変更幅
- 完了画面で最も価値がある情報
- 全記録の編集、復旧、中断に関する不足
- 他アプリから移行できる実データ形式
- 提案理由と引用文献の理解しやすい見せ方

## 3. 調査方法

### R1 今日の行動ニーズ

1. TestFlightの仮名化利用分析から、提案表示、採用、完了、差し替えを集計する
2. 目的、経験レベル、曜日、回復状態別に比較する
3. テスターへ次の質問を行う
   - 今日の提案を見て何をすればよいか分かったか
   - 不要だった行動は何か
   - 足りなかった行動は何か
   - 3件は多いか少ないか
4. 少人数では数値だけで断定せず、操作ログと自由記述を併記する

前提作業:

- 表示、開始、完了、差替え、拒否を区別する研究用イベントを追加する。
- 目的、経験、readiness、位置、sourceは列挙値として保持する。
- 健康値、記録値、自由記述、写真、位置は送らない。
- 同意しない利用者を分母へ混ぜず、同意率を別に記録する。

成果物:

- 目的別DailyAction候補表
- 頻度ルール
- 主行動と補助行動の選定規則
- 表示しない条件

### R2 目的別の科学的根拠

既存Evidence RAGを使い、以下を目的別に評価する。

- 筋力・筋肥大トレーニングの頻度、量、強度、休憩
- 減量時の筋トレ、活動量、エネルギー、タンパク質
- 睡眠、疲労、HRV、安静時心拍の扱い
- 体重、腹囲、写真を記録する妥当な頻度
- 復帰時の負荷低減と中止条件

各項目に対象者、研究種別、確度、適用限界を付ける。医学的診断には使わない。

### R3 競合調査

対象:

- Fitbod
- Strong
- Hevy
- JEFIT
- StrongLifts
- MacroFactor
- Apple Fitness / Health
- 回復スコアを扱う主要アプリ

比較項目:

- 起動直後に何を提示するか
- 目的と回復状態の反映
- 計画変更のタイミング
- ユーザー承認の有無
- 中断・復帰
- 完了直後の表示
- データの編集、輸出、移入

### R4 AI計画改訂

過去履歴を使ったオフライン評価セットを作る。

- 順調に達成
- 同重量で連続未達
- 高RPE
- 低RPEで余裕あり
- 睡眠不足
- 長期休止から復帰
- 器具変更
- 時間短縮

専門知識とルールで期待結果を定義し、AI提案との差を確認する。

### R5 完了画面

次の3案を比較する。

- A: 次回提案を最上部
- B: 達成・PRを最上部
- C: 今回の数値を最上部

評価項目は、理解時間、次回計画への反映率、詳細画面を開いた割合とする。

### R6/R7 データ安全性

全データ型について以下を表にする。

- 作成
- 閲覧
- 編集
- 削除
- Undo
- ゴミ箱復元
- エクスポート
- インポート
- 派生値再計算
- iPhone/Watch同期

### R8 移行形式

優先調査順:

1. BodyMode JSON
2. Strong CSV
3. Hevy workout CSV
4. Hevy measurements CSV
5. Apple Health XML
6. JEFIT CSV
7. 汎用CSV
8. Fitbodは正式な一括出力手段を確認後に判断

公式説明だけでパーサーを作らない。各形式について、個人情報を除去した実ファイルを複数取得する。

確認項目:

- ヘッダーと型
- 日付、時刻、タイムゾーン
- kg/lb
- 種目名とカスタム種目
- 自重、追加重量、アシスト重量
- セット種別
- RPE/RIR
- 距離、時間
- 重複識別子
- バージョン差

### R9 根拠表示

一文、判断材料、引用文献の3層案を作り、次を確認する。

- 一文だけで行動できるか
- 文献が個別判断を直接証明すると誤解しないか
- データ不足と低信頼を理解できるか
- DOI/PubMedリンクを必要な人だけ開けるか

## 4. 調査ゲート

実装計画を確定できる条件:

- R1〜R9の成果物が揃っている
- 未解決事項が「実装中に決める」状態で残っていない
- 安全性とデータ損失に関するP0判断が確定している
- 移行Wave Aの実ファイルを取得済み
- AI計画改訂の期待結果セットがレビュー済み
- TestFlightの実利用データまたは不足理由が記録されている

## 5. 調査後の判断

調査完了後に各候補を次のいずれかへ分類する。

- 実装する
- 小規模実験する
- 詳細モードだけに置く
- 正式公開後まで保留する
- 実装しない

分類後にのみ、`bodymode_core_experience_implementation_plan_2026-08-16.md`を確定版へ更新する。
