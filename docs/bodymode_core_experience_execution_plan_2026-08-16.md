## 1. 目的

BodyModeを「多機能な記録アプリ」から、次の循環が途切れないAIトレーナーへ進化させる。

1. 今日やることが分かる
2. 迷わず実行できる
3. 中断や誤操作でも記録を失わない
4. 実績から次の計画が改善される
5. 提案理由と科学的根拠を確認できる
6. 他アプリの履歴を持ち込める

採用方針:

- 既存機能を削除せず、詳細モードへ整理する
- ホームと実行画面は単純化する
- 判断、復旧、移行、分析は高機能化する
- AIが停止しても記録とローカル提案は利用可能にする

## 3. 今日提示する行動の設計

### 3.1 表示構造

ホームでは「3枚の独立した提案」ではなく、1つの `Today Plan` として表示する。

- 主行動: 必ず1件。最も結果へ影響する行動
- 補助行動: 0〜2件。主行動の成功または回復を支える行動
- 主CTA: 画面上に1つだけ
- 各行動: 完了条件、現在値、期限、短い理由、遷移先を必須とする

例:

```text
今日の計画

主行動  背中・肩 45分                [開始]
補助     タンパク質 118 / 150g
補助     23:30までに就寝準備

Jun: 背中は4日空き、回復状態も良好です。
```

### 3.2 行動候補

#### トレーニング

- 指定計画を実施
- 短縮メニューを実施
- 低負荷メニューへ変更
- 有酸素運動
- モビリティまたは回復運動
- 完全休養

#### 栄養

- タンパク質目標
- 摂取カロリー目安
- 脂質上限への注意
- 食物繊維または野菜の追加
- 水分補給
- 食事写真または食事内容の記録

#### 身体・健康記録

- 体重記録
- 腹囲記録
- 体型写真セット
- 疲労感入力
- Health共有状態の確認

#### 日常活動・回復

- 歩数
- 睡眠時間
- 就寝準備時刻
- 軽い散歩
- 座位時間の中断

### 3.3 目的別優先順位

| 目的 | 主行動候補 | 補助行動候補 |
| --- | --- | --- |
| 筋肥大 | 部位別筋トレ、短縮筋トレ、回復 | タンパク質、カロリー、睡眠 |
| 筋力向上 | 主要種目、強度調整、休養 | 睡眠、RPE入力、タンパク質 |
| 減量 | 筋トレ、有酸素、歩数 | カロリー目安、タンパク質、体重 |
| 体型改善 | 筋トレ、部位バランス調整 | 写真、腹囲、タンパク質 |
| 健康維持 | 歩行、全身運動、回復 | 睡眠、食事バランス、体重 |
| 復帰 | 低負荷運動、短縮運動、休養 | 疲労感、痛みがある場合の中止案内、睡眠 |

医療的な診断や治療指示は行わない。

### 3.4 選定制約

1. 主行動は1件だけにする
2. 同じ種類の行動を重複させない
3. 測定行動は原則1日1件以下にする
4. 食事関連は最大1件にまとめる
5. 実行不能な器具、時間、場所を要求しない
6. 前日に未達でも機械的に繰り越さない
7. 疲労や睡眠不足が強い場合は強度を上げない
8. 完了を機械判定できない行動はワンタップ完了を用意する
9. データ不足時は断定せず、信頼度を下げる
10. 小さなデータ変化で朝の計画を頻繁に変更しない

### 3.5 選定方式

ローカルエンジンで候補を採点し、即時表示する。

```text
score = goalImpact
      + urgency
      + feasibility
      + recoveryFit
      + continuityValue
      - inputBurden
      - recentRepetition
      - riskPenalty
```

AIは候補の追加、優先順位、目標値、理由を補正する。AI補正後も選定制約をローカルで再検証する。

## 4. AIによる計画改訂

### 4.1 改訂トリガー

- 計画を2〜3回実行して基礎データが揃った
- 同じ種目で目標達成または未達が連続した
- 直近2〜4週間で進捗が停滞した
- 疲労、睡眠、痛みの自己申告から負荷調整が必要
- 利用可能な曜日、時間、器具が変更された
- ユーザーが「計画を見直す」を実行した

### 4.2 AI入力

- 目的と具体的な到達像
- 現在の計画
- 直近2〜4週間の種目別実績
- 達成率、RPE、推定強度、ボリューム、頻度
- 睡眠、疲労、安静時心拍など利用許可済みの回復情報
- 利用可能な曜日、時間、器具
- 過去に承認・拒否した提案
- RAGから得た目的別の科学的根拠

### 4.3 提案画面

AIは勝手に計画を変更しない。最初に変更概要を提示する。

```text
Junから計画の見直し

胸の主要種目は伸びています。
背中の週間セット数が目標より少なく、脚は疲労が残っています。

変更候補
- ベンチプレス 60kg → 62.5kg
- ラットプルダウン 3セット → 4セット
- 脚の日を1日後ろへ移動

[変更内容を見る] [今回は変更しない]
```

承諾後に保存先を二択で選ぶ。

1. 新しい計画として作成
2. 既存の計画を更新

既存更新時は変更前スナップショットを保存し、取り消せるようにする。新規作成時は元計画を残し、名称と開始日をユーザーが確認する。

### 4.4 差分単位

- 種目の追加、削除、置換
- 種目順
- セット数
- 重量
- 回数
- RPE/RIR
- 休憩時間
- 上げ下げテンポ
- 曜日、頻度、セッション時間

### 4.5 提案結果の学習

`PlanRevisionProposal` に提案、承認結果、適用先、実行後結果を保存する。

- acceptedAsNew
- acceptedAsUpdate
- rejected
- reverted
- effectivenessUnknown
- improved
- unchanged
- worsened

## 5. 完了画面の課題と改修

現状の完了画面は「何をしたか」を数値で示すが、ユーザー自身が数値を解釈して「次回どうするか」を決める必要がある。これはBodyModeの中心価値と逆になる。

改修後の優先順位:

1. トレーナーの短い評価
2. 次回の具体的な変更提案
3. `新しい計画にする` / `既存計画を更新` / `今回は変更しない`
4. PRや達成事項
5. 達成率、ボリューム、目標差などの詳細

提案を生成できない場合も、ローカルルールで「維持」を提示する。完了保存はAI通信を待たない。

## 6. 全記録の編集・削除・復元

### 6.1 対象

- トレーニング計画
- トレーニング履歴と各セット
- 食事と食材内訳
- 身体数値
- 体型写真セット
- 主観疲労・回復
- ジム訪問
- AI記憶
- AI提案と計画改訂履歴

### 6.2 共通仕様

- 詳細画面から編集可能
- 削除直後にUndoを表示
- 削除データは30日間ゴミ箱へ保存
- ゴミ箱から個別復元・完全削除が可能
- 編集後に派生値、グラフ、DailyAction、AI Contextを再計算
- HealthKit由来データは「BodyMode内の表示除外」と「Healthから削除」を分ける
- 変更日時と変更元を保持する

## 7. 中断・再開・キャンセル

### 7.1 自動保存

- セット値、完了状態、種目順、休憩、経過時間を変更ごとに保存
- アプリ終了、クラッシュ、端末ロック、Watch切断後も復帰可能
- iPhoneとWatchは同じ `ActiveWorkoutSession` を共有
- 競合時は更新時刻だけでなくセット単位の変更をマージする

### 7.2 明示操作

実行中画面に以下を用意する。

- `中断`: 状態を保存してホームへ戻る
- `再開`: ホーム、計画、Watchから同じ状態へ戻る
- `完了`: 履歴へ確定保存する
- `キャンセル`: 保存中の実行状態を破棄する。確認を必須にする

ホームの主CTAは中断セッションがある場合、必ず `続きから` を優先する。

## 8. 提案理由と科学的根拠

### 8.1 3層表示

1. 一文: 「背中は4日空き、睡眠状態も良いため通常強度です」
2. 判断材料: 使用した記録、期間、データ不足、信頼度
3. 根拠: 文献名、年、対象、要点、文献リンク

### 8.2 引用ルール

- RAGで取得できた文献だけを引用する
- DOI、PubMed、出版社URLのいずれかを保持する
- 文献が直接支持していない個別判断は「記録からの推定」と分ける
- 研究結果とBodyMode独自ルールを混同しない
- 最新性だけでなく、レビュー、メタ分析、ガイドラインを優先する
- 引用不能でも提案は可能だが「直接使える文献なし」と表示する

## 9. データ移行

### 9.1 対応優先順位

1. BodyMode JSONバックアップの復元

3. Hevy workout CSV
4. Hevy measurements CSV

7. JEFIT CSV
8. Strava cardio import
9. その他、ベータ参加者から実ファイル提供が得られたアプリ

JEFITはエクスポート可能だが複数セクションを含む形式であるため、匿名化された実ファイルを複数取得してからパーサーを確定する。

#### 調査継続

- Fitbodは公開された一括エクスポート形式を確認できないため、ユーザーが取得できる正式手段と実ファイルを確認してから判断する

5. 未対応種目だけユーザー確認
6. 件数、期間、警告、重複候補をプレビュー
7. 取込実行
8. 取込単位で一括取り消し可能

### 9.3 正規化

- kg/lb変換
- 日時とタイムゾーン

- 重複検出
