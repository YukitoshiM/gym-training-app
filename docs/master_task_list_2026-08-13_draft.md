## 0. 運用ルール

### 状態

| 状態 | 意味 |
|---|---|
| 追加待ち | 利用者から続きの要望を受け付けている |
| 未着手 | 要件は判明しているが実装していない |
| 設計待ち | 方針決定またはAPI・UX設計が必要 |
| 一部対応 | 基盤はあるが要望を満たし切っていない |
| 実装済み・未配布 | コードと自動テストは完了したがTestFlightへ未配布 |
| 配布済み・確認待ち | 修正ビルドは配布済みだが実機または利用者確認が残る |
| 要検証 | 実装済みだが実機・運用データでの確認が残る |
| 再発・調査中 | 一度修正した課題が新しいビルドで再報告された |
| 利用者作業 | アカウント、契約、公開情報など利用者の操作が必要 |
| 保留 | 初回公開には入れず、条件が整ってから判断する |
| 無期限保留 | 正式リリース後もアクティブタスクへ入れず、利用者の明示的な再開判断がある場合だけ再検討する |
| 完了 | 実装と必要な検証が完了し、再発時の正規IDも記録されている |

### 優先度

既存文書にあるP0〜P3は出典情報として保持するが、追加受付完了後に全体を再評価する。

- `P0`: 配布・安全性・主要導線を止める
- `P1`: 次ビルドで強く改善したい中核体験
- `P2`: 中核価値を深める拡張
- `P3`: 将来構想または検証後に着手
- `TBD`: 追加受付後に決定
