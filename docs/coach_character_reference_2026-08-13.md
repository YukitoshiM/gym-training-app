# BodyMode AIトレーナー キャラクター設計リファレンス

更新日: 2026-08-13  
状態: **設計案・追加受付中・未実装**

## 1. 目的

ユーザー提供の現場写真6枚から、パーソナルトレーナーの人物紹介で信頼と相性を伝える構造を抽出し、BodyModeのAIトレーナー設計へ活用する。

参考にするのは、専門性、得意なユーザー、指導方針、実績の伝え方、重点領域の可視化である。実在人物の名前、顔、連絡先、写真、経歴、資格、文章はアプリへ流用しない。

## 2. 写真から得られた設計パターン

現場の紹介では、次の情報が一画面で把握できるようになっていた。

- 顔と名前: 誰に相談するか
- 一言の約束: 何を助けてくれるか
- 得意なユーザー: 初心者、一般、競技者、復帰中など
- 専門領域: 筋肥大、体型改善、減量、栄養、機能改善、回復、競技力
- 指導アプローチ: 数値、習慣、姿勢、回復、競技準備など
- 経験や資格: 信頼できる理由
- レーダー表示: 得意分野の違い

BodyModeでは、この構造を「AIが何を重視して提案するか」の説明へ置き換える。AIは現実の資格や実務経験を持たないため、架空の資格・受賞歴・指導年数は表示しない。

## 3. 3層のキャラクター構造

キャラクターを一枚の人物設定へ固定せず、以下を独立させる。

| 層 | 役割 | 例 |
|---|---|---|
| `CoachPersona` | 顔、名前、ビジュアル上の親しみ | Aiko、Leo、Maya、Noor、Diego、Priya |
| `CoachingStyle` | 言葉の温度と伝え方 | 穏やか、率直、論理的、鼓舞型、慎重 |
| `CoachExpertiseProfile` | 何を重視して判断するか | 減量、筋肥大、筋力、体型改善、健康維持、復帰 |

これにより、どの外見のトレーナーでも、どの目的・話し方を担当できる。性別、人種、年齢、体型と専門性を結び付けない。

## 4. 専門プロファイル

既存APIの6つの`coach_id`を維持し、それぞれに人間が理解しやすいプロフィールを持たせる。

| coach_id | 一言の約束 | 得意なユーザー | 主な進め方 |
|---|---|---|---|
| `fat_loss` | 無理なく落とし、戻りにくい習慣を作る | 減量初心者、食事管理が続かない人 | 体重傾向、腹囲、食事、活動量、空腹対策を小さく調整 |
| `hypertrophy` | 回復できる量で筋肉を着実に増やす | 筋肥大、フィジーク志向、部位を伸ばしたい人 | ボリューム、漸進性過負荷、PFC、睡眠、部位バランスを統合 |
| `strength` | 疲労を管理しながら扱える力を伸ばす | 主要種目の記録向上、競技力向上 | 重量、回数、RPE、テンポ、回復、PR傾向から次の負荷を判断 |
| `body_recomposition` | 数字と見た目の両方から身体を整える | 体型改善、細マッチョ、見た目重視 | 写真、腹囲、体重、筋力、食事の変化を同じ期間で比較 |
| `wellness` | 体調を崩さず、動ける毎日を続ける | 健康維持、初心者、生活習慣改善 | 睡眠、歩数、疲労、無理のない運動、継続性を優先 |
| `return_to_training` | 焦らず段階的に運動へ戻る | ブランク明け、疲労が強い人、復帰中 | 主観状態と運動反応を確認し、負荷・量・頻度を保守的に調整 |

「復帰」は診断、治療、リハビリテーションの代替ではない。痛みや異常がある場合は運動中止や専門家相談を案内する。

## 5. 指導フォーカスの7軸

現場のレーダーチャートを参考に、以下の7軸を用いる。

1. 筋肥大
2. 体型改善
3. 減量
4. 食事・栄養
5. 動作・活動性
6. 回復・運動復帰
7. 筋力・競技力

値は`0...5`とするが、**能力、資格、医学的信頼性の点数ではない**。「提案時にその観点をどれだけ重視するか」を表す。レーダー表示だけに依存せず、VoiceOver向けの文章と「特に重視する3項目」を併記する。

## 6. プロフィールの表示項目

コーチ選択と詳細画面では、長い経歴紹介より次を優先する。

1. アバターと名前
2. 一言の約束
3. 「こんな人におすすめ」最大3件
4. 特に重視する3領域
5. 指導の進め方
6. 回答で参照する記録
7. できないこと・安全境界

推薦時は「あなたの目的が筋肥大で、最近は疲労記録が多いため」のように、選んだ理由を短く示す。推薦は決定ではなく、人物、話し方、専門性をいつでも変更できる。

## 7. AI回答への反映

専門プロファイルは単なる紹介文にせず、AIプロンプトと出力検証へ反映する。

共通の回答順序:

1. 状態や悩みを短く受け止める
2. 記録に基づく結論を先に示す
3. 判断に使ったデータと不足情報を分ける
4. 今日または次回の行動を最大3件示す
5. 重要な変更は確認を求め、勝手に確定しない

専門性によって変えるもの:

- どの記録を優先して見るか
- 同じ記録から何を重点課題にするか
- 提案する行動の種類
- リスクや不足情報の確認順序

専門性によって変えないもの:

- 医療的な断定をしない
- 根拠のない数値や経歴を作らない
- ユーザーを責めない
- 記録がないことを「悪い」と扱わない
- 安全に関わる変更を黙って確定しない

## 8. ビジュアル方針

アバターは、日常の中で自然に撮影された実在感のある人物写真として統一する。

- 人種、ジェンダー、年齢、体格を多様にする
- ジム、屋外、キッチン、スタジオなど背景と撮影角度を変える
- 健康的な活力、清潔感、自信、自然な色気を表現する
- 過度な露出、性的なポーズ、極端な筋肉表現を専門性の記号にしない
- 白衣、医療器具、資格章など誤認を招く演出を使わない
- 人物間で照明、肌、歯、体型を過剰に均質化せず、生成画像らしい不自然さを減らす
- 小さい円形表示と大きなプロフィール表示の両方で本人を識別できる

同一人物のアセットは、ホーム、AIハブ、チャット、計画提案、食事分析、体型写真分析、週次レポートで一貫させる。

## 9. データモデル案

```swift
struct CoachExpertiseProfile: Codable, Identifiable {
    let id: CoachType
    let promise: String
    let recommendedFor: [String]
    let focus: CoachFocus
    let approach: [String]
    let preferredContext: [CoachContextKind]
    let boundaries: [String]
}

struct CoachFocus: Codable {
    let hypertrophy: Int
    let bodyRecomposition: Int
    let fatLoss: Int
    let nutrition: Int
    let movement: Int
    let recovery: Int
    let performance: Int
}
```

初期値はアプリ同梱のバージョン付き設定として管理する。将来のAI調整でもユーザーが選んだ人物や話し方を勝手に変更しない。

## 10. 安全・権利ルール

- 提供写真は分析用参考であり、リポジトリや配布物へ複製しない
- 実在人物に似せた名前、顔、経歴、キャッチコピーを作らない
- AIにNSCA、NESTA、医療資格などを保有していると名乗らせない
- 「治す」「診断する」「怪我を予防できる」など結果を保証する表現を使わない
- 科学的根拠はキャラクターの権威ではなく、Evidence RAGの出典と確度で示す
- 推薦ロジックと表現を、性別、人種、年齢、体格による固定観念の観点でレビューする

## 11. 受け入れ確認

- 同じアバターに異なる指導スタイルと専門性を設定できる
- 同じ目標でも候補が複数表示され、推薦理由を確認できる
- 7軸が能力や資格の評価ではないと理解できる
- AI回答が選択した専門プロファイルに沿いながら、共通安全ルールを守る
- 実在人物の名前、写真、連絡先、資格、固有経歴が成果物へ含まれない
- 文字サイズ拡大とVoiceOverでも得意分野と推薦理由を理解できる
- 全AI関連画面で選択したアバター、名前、話し方が一致する
