# BodyMode 回帰テスト判定基準

更新日: 2026-08-14

## 1. 目的

すべての修正で全回帰を行わず、変更リスクと実機の品質シグナルに応じてテスト範囲を決める。判断は実装前または配布前に記録し、失敗後に都合よく基準を変えない。

## 2. テストレベル

| レベル | 内容 | 主な用途 |
|---|---|---|
| L0 | ビルド、lint、設定・文書検査 | 文言、文書、配布設定だけの変更 |
| L1 | 変更箇所の単体テストと直接のUIテスト | 局所的な表示・ロジック修正 |
| L2 | L1に加え、影響する機能領域の単体・UIテスト | 1機能内の状態管理、通信、バックグラウンド処理 |
| L3 | 単体全件、iPhone UI全件、Watch UI全件 | 横断変更、累積変更、正式公開候補 |

L3は`scripts/run_parallel_simulator_regression.sh`を使用する。スクリーンショット専用テストと実機必須項目は既存のゲート定義に従う。

## 3. L3を必須にする条件

次のどれか1つに該当すれば、点数に関係なくL3とする。

1. App Store正式公開または審査提出用のリリース候補
2. 永続化形式・データ移行・全データ削除・認証・権限・プライバシー・課金の変更
3. AppStore、ルートナビゲーション、共通入力部品、Watch同期プロトコルなど、3画面以上へ波及する共通基盤の変更
4. 異なる原因のクラッシュが2種類以上、または同じクラッシュが2人・2端末以上で再現
5. P0が1件、または直近7日で未解決P1が4件以上
6. 前回L3成功点が不明、または成功から14日を超えた状態で外部配布する
7. 依存パッケージ、Xcode/Swift、entitlement、署名、Build Configurationを更新する

単一端末で再現した局所的なクラッシュ修正は、自動的にL3とはしない。変更先が1機能に閉じ、再現テストと隣接UIテストがある場合はL2でよい。

## 4. 通常の判定スコア

必須条件に該当しない場合、次の5軸を各0〜3点で評価する。

### 変更範囲

| 点 | 基準 |
|---:|---|
| 0 | 文書・文言・画像だけ |
| 1 | 1機能、production file 1〜2個 |
| 2 | 2機能、または共通部品1個 |
| 3 | 3機能以上、iPhone/Watch/Serverを横断 |

### 障害影響

| 点 | 基準 |
|---:|---|
| 0 | 見た目だけ |
| 1 | 操作不便、回避可能 |
| 2 | 保存・通信・通知・バックグラウンド処理の失敗 |
| 3 | クラッシュ、データ消失、セキュリティ、健康データ誤表示 |

### 前回L3からの累積

| 点 | 基準 |
|---:|---|
| 0 | production file 1〜2個、差分150行以下、2 commit以下 |
| 1 | 3〜7個、151〜500行、または3〜5 commit |
| 2 | 8〜15個、501〜1,000行、または6〜10 commit |
| 3 | 16個以上、1,001行以上、11 commit以上、または基準点不明 |

複数条件が異なる点になる場合は最大値を採用する。

production fileは`GymTrainingApp`、`GymTrainingWatchApp`、`Shared`、`local_llm_server`、配布設定内の実行コードを指す。テスト、文書、生成済みXcode project、`.build`は変更量から除外する。

### 実機フィードバック

| 点 | 基準 |
|---:|---|
| 0 | 新規問題なし |
| 1 | 同一領域の軽微な要望が1〜2件 |
| 2 | P1が2〜3件、または同一端末で同じクラッシュが再発 |
| 3 | P0、P1が4件以上、異なるクラッシュ2件以上 |

### 配布段階

| 点 | 基準 |
|---:|---|
| 0 | ローカル開発のみ |
| 1 | 内部・少人数TestFlight |
| 2 | 外部TestFlightの通常更新 |
| 3 | App Store正式公開候補 |

## 5. 合計点と実行範囲

| 合計 | 判定 |
|---:|---|
| 0〜3 | L0またはL1 |
| 4〜6 | L2 |
| 7以上 | L3 |

境界で迷う場合は1段階上げる。ただしL3実行中に方法の試行錯誤を始めず、既知のスクリプトを1回だけ使う。

## 6. 配布別の最低条件

### 局所ホットフィックス

- 不具合を再現またはログで原因特定
- 修正箇所の単体テスト
- 直接影響するUIテスト
- `scripts/testflight_preflight.sh`

### 通常のTestFlight更新

- 判定スコアに応じたL1〜L3
- 変更したiPhone/Watch領域のテスト
- `scripts/testflight_preflight.sh`
- 実機でしか確認できない項目をWhat to Testへ記載

### App Store正式公開

- L3成功
- `scripts/release_production_preflight.sh <archive>`成功
- 実機受入とApp Store提出チェックリスト完了

## 7. 実行記録

配布前に次を短く残す。

```text
基準点: <前回L3成功commit/date>
変更範囲: <点と理由>
障害影響: <点と理由>
累積: <点とfiles/lines/commits>
実機フィードバック: <点と件数>
配布段階: <点>
強制条件: <なし/該当項目>
判定: <L0/L1/L2/L3>
実行結果: <pass/fail/skipと証跡path>
```

L3成功時はGit SHA、日時、件数、summary pathを`docs/regression_report_2026-08-13.md`へ追記し、次回の累積基準点にする。中断したL3は成功点として扱わない。
