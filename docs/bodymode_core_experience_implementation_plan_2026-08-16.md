## 4. Wave 2 Today Plan

実装進捗:

- [x] 既存計画を優先して直接開始
- [x] 計画なし時のAI自動生成
- [x] AI接続失敗時のローカル完成メニュー
- [x] 種目、順番、セット数、重量、回数、休憩の生成
- [x] RPE目安、上げ下げテンポ、Watch同期
- [x] 所要時間の自動算出
- [x] 代替種目候補の生成と表示
- [x] 行動と軽い理由を同じカードへ表示
- [x] `今回だけ実行`と`保存して開始`の選択
- [x] 日次提案の論文根拠を`根拠を見る`へ統合

- 調査で確定した目的別行動カタログ
- ローカル選定エンジン
- 主行動1件、補助0〜2件
- Today Plan 1ブロック
- 主CTA 1個
- トレーニング提案は既存計画から選ぶことを最優先とする
- 既存計画に適切な候補がない場合は、AIが種目、順番、セット数、重量、回数、RPE、休憩、テンポ、所要時間、代替種目まで入力済みの計画を生成する
- ユーザーへ空の計画作成画面を見せず、完成した提案を`保存して開始`または`今回だけ実行`できる状態で提示する
- AI未接続時は、目的、経験、利用器具、前回実績からローカルで完成済み計画を生成する
- 通常表示は結論を先にし、行動と軽い理由を同じカードへまとめる。個人記録や論文の詳細は`根拠を見る`へ置く
- AI状態の縮小
- 高度情報を詳細モードへ移動

受入条件:

- AI通信なしで起動直後に実行可能な主CTAが出る
- 行動に完了条件、理由、遷移先がある
- 矛盾または実行不能な行動を出さない
- 既存計画がある場合は新規生成せず、その計画を提案して直接開始できる
- 既存計画がない場合も、ユーザーが種目や数値を一から入力せず実行可能な計画へ到達できる

### 4.1 全体UX方針

BodyModeの標準経路は次の順とする。

```text
自動取得 → 自動判断 → 完成した内容を提示 → ワンタップで実行
→ 自動記録 → 次回へ反映
```

手動入力と直接編集は、AI提案の変更、実績との差異、器具の利用不可、AI未接続などを補う経路として維持する。自動化の都合で手動経路を削除せず、手動入力を標準経路にも置かない。

- [x] 完了画面の達成率に応じた見直し導線
- [x] 実績、目的、回復、器具、時間をAI Contextへ入力
- [x] AIによる具体的な全セットの改訂案生成
- [x] 承認前は既存計画を変更しない
- [x] `新しい計画として作成`
- [x] `既存計画を更新`
- [x] `今回は変更しない`
- [x] 更新直後の取り消し
- [x] 改訂提案と承認結果の永続履歴
- [x] iPhone/Watch共通の自動改訂トリガー
- [x] 変更前後の種目・セット・重量・回数・RPE・休憩差分
- [x] 再起動後も有効な改訂取消
- [x] 改訂後の次回実績による効果判定とAI Contextへの反映
- AIは構造化候補の説明、優先順位、代替案に限定
- 入力候補とAI出力の1対1対応、欠落、重複、範囲外変更を検証
- 変更差分
- 新規・改訂のどちらも、具体的な全セットを生成してから差分とともに提示する
- 達成・PRを先頭、次回仮提案を次点に置く完了画面の暫定案

受入条件:

- 承認前に計画を書き換えない
- AI自由文を計画データへ直接適用しない
- 候補の欠落・混同・重複時は適用せずローカル候補を表示する
- 新規作成と既存更新の両方を選べる
- 更新前へ戻せる
- AI停止時も完了保存できる

## 6. Wave 4 根拠表示

- 一文の理由
- 使用した個人記録、期間、欠測、信頼度
- 文献名、年、研究種別、リンク
- 個人記録からの推定と一般的研究知見を分離
- 根拠がない場合の明示

受入条件:

- 存在しない文献を表示しない
- 引用元を開ける
- 文献が個人への効果を保証すると誤認させない

## 10. 実装順の確定方法

調査完了後、各候補を次の軸で採点する。

- ユーザー価値
- 発生頻度
- データ損失・安全リスク
- BodyModeの差別化への寄与
- 実装と運用コスト
- 検証可能性

採点結果によりWaveの順番と範囲を更新する。現時点のWave番号は確定納期を意味しない。
